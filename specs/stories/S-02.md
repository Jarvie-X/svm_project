# S-02 — Approve audience and result language

## Technical implementation specification

### Objective

Define the learner-facing language for the Wine Recognition demonstration so
that a customer can approve the intended audience, category names, accuracy
presentation, and measurement guidance before release. This story is a
human approval point; the repository records the proposed wording and the
approval evidence, but does not claim approval on the customer's behalf.

### Intended audience

The primary audience is learners who are being introduced to classification
with a small, familiar demonstration. Reviewers and product stakeholders are
secondary audiences and need enough context to distinguish a demonstration
from a production-quality wine decision system.

### Proposed displayed language

- **Title:** Wine sample classification demonstration
- **Category wording:** Class 0, Class 1, and Class 2 (the three recognized
  categories in the approved Wine Recognition dataset). These labels are
  dataset target names, not wine varietals or quality grades.
- **Result wording:** `Predicted category: Class <n>` and
  `Prediction confidence: <percent>%` when the product presents a model
  result. If accuracy is shown, label it `Held-out test accuracy` and include
  the evaluation split or test sample count.
- **Measurement guidance:** Explain that each sample is represented by 13
  chemical measurements. Show measurement names and units from the approved
  dataset metadata where available; do not imply that a learner should
  collect measurements without the appropriate laboratory equipment.
- **Accuracy guidance:** Accuracy is an evaluation summary over labeled test
  samples, not a guarantee for an individual prediction. Report the sample
  count and evaluation method alongside the percentage, and do not describe
  the result as a wine quality, safety, health, or purchasing recommendation.

### Implementation

- Keep the approved wording in `docs/customer-approval/S-02.md` as the
  reviewable source for learner, reviewer, and stakeholder copy.
- Add a customer sign-off table with separate decisions for audience,
  category wording, accuracy presentation, and measurement guidance.
- Record technical verification in `docs/verification/S-02.md`; it must
  distinguish automated checks from the customer decision and must not mark
  the customer approval complete without an explicit customer response.

Review `docs/customer-approval/S-02.md` with the customer and record the
