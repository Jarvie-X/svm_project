# S-04 — Add guided prediction entry

## Technical implementation specification

### Objective

Provide a self-contained guided entry point for predicting one Wine
Recognition dataset category. A reviewer can see all thirteen measurements,
enter a complete sample, and receive one category without needing to know the
classifier internals.

### Implementation

- Add `wine_prediction.py` with the approved dataset's thirteen feature names
  and dataset-derived measurement guidance (including units where the
  metadata provides them).
- Expose a structured `predict_measurements` callable that validates exactly
  thirteen finite numeric values, rejects missing, non-numeric, non-finite, or
  non-positive measurements with field-specific correction messages, then
  trains the same scaled SVM workflow used by S-03 on the full approved
  dataset and returns one of `Class 0`, `Class 1`, or `Class 2`.
- Expose `measurement_guidance()` so clients can render every field and its
  correction guidance without duplicating the feature list.
- Add a non-interactive-by-default command-line entry point. With no
  arguments it prints the thirteen guided fields and accepts one value per
  prompt; `--values` supports scripted/reviewer verification. Validation
  errors are understandable, identify the field, and cause a non-zero exit.
- Do not present the prediction as wine quality, safety, health, or purchasing
  advice. Keep the category labels aligned with S-02 and describe the output
  as an educational demonstration.

### Verification

Run:

```text
python -m pytest -q
python -m wine_prediction --values <13 valid values>
python -m wine_prediction --values <each missing/non-numeric/non-finite/non-positive case>
```

Automated tests cover a known valid Wine dataset sample, every missing field,
representative malformed and invalid values, the complete guidance list, and
the command-line result/error behavior. Record command results in
`docs/verification/S-04.md`.
