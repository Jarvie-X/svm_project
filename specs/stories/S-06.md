# S-06 — Release the demonstration

## Technical implementation specification

### Objective

Package the completed Wine Recognition workflow as a release-ready product
shell for learners, reviewers, and stakeholders. A single non-interactive
release command must validate readiness, run the held-out evaluation, and run
one supplied prediction while preserving the approved educational guidance
and category wording.

### Implementation

- Add `wine_demo.py` as the release entry point. It accepts the same thirteen
  values as the guided predictor through `--values`, performs a readiness
  check, reports the deterministic held-out accuracy, and then presents the
  complete prediction result.
- Reuse `wine_readiness.check_readiness`, `wine_classifier.run_classification`,
  and `wine_prediction.predict_measurements`; do not create a second model or
  duplicate the approved feature/category definitions.
- Keep `Class 0`, `Class 1`, and `Class 2` as the only category wording. Show
  all thirteen measurement fields and explain that the result is a dataset
  label, not wine varietal, quality, safety, health, or purchasing advice.
- Return a non-zero status with actionable correction text for missing,
  malformed, non-finite, or non-positive input, and a non-zero status when
  runtime or dataset readiness fails.
- Update `README.md` with the release command, scripted verification command,
  input expectations, and the approved educational context. Add automated
  release-shell tests covering successful, repeated, and invalid flows.

### Verification

Run:

```text
python -m pytest -q
python -m wine_demo --values <13 valid values>
python -m wine_demo --values 1 2
python -m wine_demo --values <13 valid values>
```

Confirm the release command completes without prompts, reports at least 90%
held-out accuracy, displays the complete input and prediction explanation,
and rejects invalid input. Record the end-to-end review in
`docs/verification/S-06.md`.
